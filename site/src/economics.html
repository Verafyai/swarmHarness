    Proof packing

    A proof covers one request of up to 1,024 tokens, about 750 words. That limit comes from today's prover, not the model: it has to keep and check every intermediate value for every token. Proof packing fills those requests as tightly as possible and stops paying for the same proof twice. It has four parts, and the first three run today in packages/pack.

    1. Atomize. Each contract is broken into atoms: small questions that ask one thing (yes or no, a choice, or a bounded integer) and carry only the facts that decide it, each citing a pinned source. An exact composition rule turns the atoms' answers back into the contract's outcome. That rule is code, integer math only, and any UNKNOWN atom sends the contract to its declared fallback instead of a guess. Plain dense English, never invented shorthand: models read English tokens best.
    2. Dedupe. The same atomic question over the same pinned facts has the same hash. Thirty markets that all hinge on "did the Fed cut rates on December 10?" share one slot and one proof.
    3. Pack. Atoms are packed first-fit by size into 1,024-token requests, about 16 to 18 per request in our tests, each in a numbered slot with its own answer line. The slot order is shuffled by the block hash, so nobody chooses their neighbors. A reply that misses or mangles any slot is rejected whole. Contracts that must stand alone opt out.
    4. Prove once, verify many. Today only one model can be proven, and with integer weights and greedy decoding, every juror running it on the same input gets the same answer. So each packed request is proven once, by a prover drawn from the block hash, and the other jurors become verifiers. Lab diversity returns as soon as a second model is provable: one proof per distinct model.
    The safeguard. A proof shows the model answered the atoms correctly, not that the atoms and the rule capture the original question. So every atom plan is either agreed by the contract's parties before funding, or checked by a cheap unproven panel from several labs (the fidelity check), and auditors spot-check its citations. A plan that drops the deciding fact or reaches a different outcome fails the check, and that contract runs unpacked.
    What the numbers show. Once contracts are packed, proving stops being the big cost. At 1,000 contracts, the proving GPU costs about $1.29 and the fidelity checks about $3.26 (modeled). The next savings come from cheaper checks, not cheaper proofs.

    Where a fast screen fits (Jev)

    A System 1 model such as TypeSafe's Jev returns a typed answer with a calibrated probability in 70 to 500 ms for about $0.0004 a decision (vendor-reported, not reproduced). Atoms are exactly the shape it reads. It fits in three places:

    • Screening the fidelity checks, the biggest cost after packing. Clear plans pass on the screen; unclear ones go to the multi-lab panel.
    • Settling low-stakes atoms, only where a contract allows it. Those atoms are fast and cheap, but not proven.
    • Triage and sizing: its probability decides which atoms need a proof at all, and how big the jury should be.

    It can't be the court. It's one hosted, closed model, so it adds no lab diversity and can't carry a proof of inference, and on its vendor's own benchmark it scored 67.8% against 73 to 74% for frontier models. Calibrated isn't the same as correct.

    What packing does not change

    • Warm-up is paid per proving session, not per block. A proving service that stays warm across blocks pays for idle hours instead, which the utilization input models.
    • A long document still has to be briefed; a proven juror never reads more than 1,024 tokens at once. Long-document judgment is better run unproven (L1) with a diverse jury and auditors, or by proving only the deciding excerpts.
    • Prove once trades jury diversity for proof while one model is provable. Say so on any contract that uses it.
